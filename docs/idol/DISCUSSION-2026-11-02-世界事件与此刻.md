## 0. 这次讨论是怎么来的

Flora 玩了一段时间爱豆小手机，发现：

- 她设定了很多 app 和功能，但**最爱用的是「此刻」**。
- KakaoTalk 聊天和 KKT 动态都觉得「很人机」；反而是此刻里每个人都生动很多。
- 她现在用此刻，主要是偶尔去周评、录个很无聊的任务；这些时刻本身也不咋有意思。
- 她特别爱玩的是**在此刻里和角色发展感情**。但她也想：能不能把整个生活都融进此刻，让事业、自己的生活也很有意思，而不只是恋爱。
- 她觉得现在的「提醒事项 / 世界事件发动机」像在**发布任务**，不像在让她**体验生活**。
- 她说的「锚点」不是「我去看演出、谁看到我」，而是**别人真的有事情在发生，她可以参与其中**。
- 她希望地图上是**真正的爱豆世界**（弘大校庆演出的团、明洞拍综艺的明星、签售会、演唱会），而不是她自己的小生活圈。
- 她不希望 AI 自己发展剧情——她觉得那样很无聊；她自己开剧情才玩得有意思，但每天想灵感很累。所以她想要的是：**每天踩地图时，有一些别人正在经历的事，她可以点进去，也可以不点。**

## 1. 她明确说过的口味 / 边界

这些是讨论里她亲自纠正过的，下一轮不要忘：

- **不要「我去看演出，然后谁注意到我 / 我被拍了」这种以她为中心的剧情。** 她说这是无聊的。
- **要「演出本身就是一个正在出事的地方」**：比如某个团最近陷入舆论风波、被黑得很惨，所以现场表现不好；或者某个成员被私生追、正在躲狗仔。她走进去时，别人的事已经进行到一半。
- **不一定是负面 / 压力局面。** 她原话大致是：「我也没说都是压力啊，你为啥要说是压力局面。它就是一个事情而已，不一定每次都是负面的。」必须是**真的在发生、可以产生后果、推动剧情的事情**（11-03 她定的说法）。
- **参不参与看她当天想不想，不需要现在决定「旁观还是改变结果」。** 系统不逼她选。
- **地图只要展现出来就行。** 她可以点进去，也可以不点；点进去可以看到事情，可以选择处理也可以不处理。**这个不需要告诉 AI**——那是戏里的自然自由。
- **不要让 AI 每次都逮着她关系最好的人。** 人物要杂：认识的、不太熟的、陌生人、圈内人、粉丝、staff 都可以。
- **不要总是 1v1。** 除了真正的约会/单独见面，世界上的事应该尽量人物多一点、像公开场合。
- **不要抢她写剧情的自由。** 发动机不是来替她写故事的，是让她在主动探索之外还能不断发现新东西。
- **命运系统不要动。** 命运是有条件触发的、在地图上有感叹号；她认可这个机制，新的「生活点 / 世界事件」跟命运分开。

## 2. 当前代码事实（只读排查结果）

### 2.1 三个地方各编各的，没有共享事件源

- **日历 · 圈内大事**：`lib/idol-calendar.ts`，KV `idol_almanac_v1`。
  - `AlmanacItem = { id, date, title, note?, kind, company? }`（`lib/idol-calendar.ts:25`）。
  - AI 每月生成 4~7 件：前辈团回归、演唱会和巡演、粉丝见面会、综艺播出、同公司前辈活动、新团出道、颁奖礼（`lib/idol-calendar.ts:184-185`）。
  - 只有「几号、什么事、一句话」，**没有地点、没有时间、没有在场的人、没有后续状态**。
- **世界发动机**：`lib/idol-events.ts`，KV `idol_events_v1`。
  - `PlannedEvent = { id, at, kind, about, people, lines, invite?, fame?, moods?, done? }`（`lib/idol-events.ts:36-49`）。
  - 每约 2 天跑一次 AI，排未来 3 天的事（`eventsTick`，`:369`；`plan`，`:192`）。
  - **完全不读日历的圈内大事**。
- **此刻**：
  - 地图只读地点（`lib/idol-stage.ts` 的 `STAGE_MAPS` / `allScenePlaces`）和命运标记（`destinyMarks`，`lib/idol-destiny.ts:111`）。
  - **不读日历，也不读世界事件**。
  - `createWorldScene(place, premise, peopleIds)`（`lib/idol-world.ts:127`）只接收一段开头和在场的人；没有事件 id、没有 phase、没有前因。所以它只能把 premise 当开头重新编。
- **世界书**：`lib/idol-worldbook.ts:56-69` 会读日历大事和 `eventsPlainFeed()`，但只是当文字背景，不驱动地图/场景。

结论：现在是三个作者各写各的。要做的不是「让三边都读同一个列表」，而是**先有一个世界事件源，三边都从它读/写**。

### 2.2 世界发动机为什么必然长成「任务发布器」

- `PlannedEvent` 的核心字段是 `at`（几点发生）、`lines`（谁说什么）、`invite`（要不要她回复）。
- 只有 `invite` 会变成 `CareerNode`，进提醒事项（`runEvent`，`lib/idol-events.ts:325-340`）。
- 其他事最多是 KakaoTalk 一句话，或者进 feed 一条记录。
- 所以不管提示词写多少「生活感」，发动机最显眼、最容易被看见的产物，永远是「某时某地要做某事」。
- 「拍 Vlog」不是世界发动机生成的，是星路每周作业：`HOMEWORK_TITLE` 里 `variety: "拍一条练习生 vlog"`（`lib/idol-starroad.ts:455-458`）；`pickHomework` 按课时/档位/最近布置加权，variety 和 visual 每周只有 0.5 节课，天然更容易被抽中（`:449`）。
- 「去办公室交资料 / 提交企划 / 讨论企划」在代码里搜不到，是 AI 每次现编的；`ENGINE_EVENTS`（`lib/idol-events.ts:165`）偏公司事务，加上 `invite` 出口，模型就容易编成行政任务。

### 2.3 没有事件状态 / 没有 phase

- 日历大事是单日文字；世界事件是一次性的 `at`；只有年末家族演唱会是写死的几步（`lib/idol-yearly.ts`）。
- 没有「回归筹备 → 回归 → 打歌 → 后续」这种持续状态。
- 没有「这件事现在走到哪一步、下一步可能怎么走」的记录。

### 2.4 没有事件重复检测 / 长历史

- 普通 `small/chance/date` 没有类型冷却、没有相似度检测、没有每周上限。
- 给 AI 的历史只有 feed 最后 8 条 + 最近 8 条人物事件，窗口很短。
- 有冷却的只有：挫折（50 天/一年 6 次/同 kind 不重复）、大事（8 天）、生病（90 天）、作业（最近 4 门加权）、日常私聊（每人 2 天）。

## 3. GPT 提出的四个研究点（Flora 认可这是主干）

1. 日历、世界发动机和「此刻」能否共享同一批事件，而不是各自编各自的。

4. 进入地点后，「此刻」能否读取事件当时的真实状态，生成对应的场景，而不是重新凭空编一件事。

## 4. 讨论后确定的方向（不是最终实现）

### 4.1 世界事件源

- 先有一个统一的 `WorldEvent` 源；日历、地图、此刻都从它读，只是看不同字段：
  - 日历：月份视图；
  - 地图：现在 / 即将发生；
  - 此刻：这一刻的真实状态。
- 世界书可以继续读它的摘要，但不是主驱动。

### 4.2 事件状态 / 锚点

- 「锚点」不是场地，是**人**。先有一条别人的线：谁在出事、谁在瞒什么、谁在争、谁快撑不住了；然后这条线刚好在一个公开场合露出来（演唱会、签售、综艺录制、校庆）。
- 事件要有 phase，例如一个团回归：
  - 一个月前：预告、公司公告
  - 两周前：预售、曲目表
  - 一周前：MV 预告
  - 当天：回归秀、MV 公开
  - 之后两周：打歌、签售、一位或争议
  - 再之后：后续、巡演、下一个团
- 每个 phase 地图上显示的地方不一样；此刻进去读到的是「现在这个阶段」，不是重新编一件事。
- 事件不一定是负面；可以是好事、坏事、尴尬事、小事。

### 4.3 地图

- 地图加一层「事件标记」：读世界事件源，按世界时间 + 地点，显示正在发生 / 马上发生的事。
- 命运标记保留，事件标记是另一层。
- 她可以点，也可以不点；点进去就是那个现场；不需要在提示词里额外告诉她「你可以走开」，那是戏里的自由。

### 4.4 此刻

- 此刻读事件状态：现在是什么 phase、之前发生了什么、谁在场、谁和谁有矛盾、哪些信息她不知道。
- 这样写出来的才是「这件事的这一刻」，不是另一件相似的事。
- 场景可以多人、可以有陌生人、可以是公开场合；不要总是抓她最亲近的人，不要总是 1v1。

### 4.5 世界发动机的职责

- 公司系统（`idol-career`、`idol-starroad`）负责日程、考核、作业、出道流程。
- 世界发动机负责**人和行业**：谁在经历什么、行业里正在发生什么、这些事会在哪个场合露出来。
- 世界发动机不再生成日常公司事务的 `chance` 邀约；`invite` 只留给真正的社交邀约和真正的外部机会。
- 不提高戏剧冲突频率，不强制恋爱，不替她决定表现/心情/身体。

### 4.6 玩家自由

- 她可以点进去，也可以不点；点进去可以处理，也可以不处理。
- 她不参与，世界继续走；但不能用「你没回消息所以 X 发生了」这种方式惩罚她。
- 发动机创造条件，不替她决定结果。

## 5. 一个草案数据模型（只是讨论用，未定）

```ts
type WorldEvent = {
  id: string;
  kind: "industry" | "company" | "personal";
  title: string;
  place: string;              // 对应此刻地图地点 key
  cast: string[];             // 团 / 人物 / 路人池
  phases: {
    at: number;
    phase: string;            // 预告 / 回归 / 打歌 / 后续…
    summary: string;          // 这个阶段世界上是什么状态
    sceneSeed: string;        // 此刻开场用的现场种子
  }[];
  currentPhase: number;
  state: string;              // 现在这件事走到哪了
  thread: string;             // 下一步可能怎么走（倾向，不是任务）
  visibility: "unknown" | "heard" | "seen" | "involved"; // 她目前知道多少
};
```

关键问题：**第 2 点（事件状态）是地基。** 没有持久状态，1 只是共享一个标题列表，3 只是把标题贴到地图上，4 还是重新编。

## 11. 2026-11-02 晚：推翻第 4、5 节，改成「围绕日历」的简单版（Flora 已确认）

> 第 4、5 节的 WorldEvent / phase / 故事线方案**作废**。以下是 Flora 和 GPT、Claude 讨论后定下的版本。

### 11.1 三样东西

- **日历圈内大事 = 活动**：还是 Flora 手动让 AI 生成（不是自动的）。**新加：每件带地点**（从地图已有地点里挑）。活动不管她去不去都照常办。
- **活动当天**：地图上那个地点名字的黑框底下多一条粉色小字「今天 · NMIXX 演唱会」（预览 `previews/地图感叹号预览3.png` 已认可）。点进去就是活动本身，可以单纯看演唱会，不硬塞剧情。
- **衍生的事**：世界发动机排事情时读日历活动，可以顺着长出事，也可以不长；也可以编和日历无关的事。
  - 时间不固定：活动前、当天、之后都行。
  - 人物不固定：陌生人、圈内别的团、staff、粉丝、认识的人；不老抓她最亲近的人；多人、公开场合。
  - 可以有后续（她去过之后，过几天可能再冒出下一步）。

### 11.2 地图「!」

- 衍生的事：**淡粉「!」**（#f5a0bc）；命运：**红「!」**（#e23a4a）。
- 位置：挂在地点名字**黑框的右上角，往下压一点**（预览 3）。
- 有小地图的地点（公司/江南/电视台/场馆）：外面那层和里面那个具体地点都挂，颜色跟着走。
- 地图上没有对应地点的事（签售会场、外景地）：**挂在最近的区域上**，点进去此刻写成真正的地方（方案 B）。
- 点进去用那件事开头，结果不替她定；不去就过期消失，不惩罚。
- **密度**：和日历每月大事差不多的量，分散在一个月里；**一天最多一个「!」**（活动当天的粉色小字不算）；不一定每天都有。
- **活动和「!」撞在同一地点同一天**：点地点弹二选一（「去看演唱会」/「那边好像有事」），有点文游的感觉。

### 11.3 砍掉

- 世界发动机里「去办公室交资料 / 提交企划」这类行政任务的 chance 邀约：**砍掉**。
