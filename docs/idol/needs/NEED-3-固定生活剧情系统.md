# SEOUL:AM｜固定生活剧情系统需求说明

> Flora 2026-11-05 深夜发来（**全部是她的设计**，GPT 只负责整理成文）。固定生活剧情 = 练习生生涯中必定出现的生活节点。全部未实现。

## 一、核心规则

固定生活剧情是练习生生涯中必定出现的生活节点。

**固定的是事件及触发条件，不固定具体剧情发展。**

- 代码负责判断日期、触发条件、安排通知及管理事件状态。
- AI 根据玩家当时的位置、同行人物、关系、背景和历史经历演绎剧情。
- 剧情主要通过「此刻」实际发生，不允许只在日历里显示文字就算完成。
- 需要提前邀请的活动，可以通过 KKT 通知玩家。
- 已确定日期的活动可以进入日历和提醒事项。
- 不强制玩家接受邀请、参加自愿活动或作出特定反应。
- 如果玩家拒绝参加某场活动，该活动仍在世界中正常发生。
- 与固定事业主线共享时间线和事件记录，不能重复安排同一场活动。

## 二、固定生活剧情

### 01｜我的生日 🎂

**触发时间**：玩家在游戏世界中的生日，每年一次。根据生日当天与玩家达到「好朋友」关系的女同期数量，选择不同分支。

- **分支 A（至少 3 位好朋友）**：几位好朋友可能秘密筹备生日聚会，也可能提前告诉玩家，邀请她一起庆祝。聚会地点、参与人物、是否准备惊喜，由人物性格与实际关系决定。
- **分支 B（1～2 位好朋友）**：一位或两位好朋友可能单独邀请玩家出去玩，或组织小范围庆祝。活动方式不固定，可以是吃饭、逛街、看电影等。
- **分支 C（没有好朋友）**：不强制安排生日聚会。认识玩家的同期，特别是熟人、朋友，仍然可能通过 KKT 送来生日祝福。

**其他规则**：生日祝福和庆祝活动可以同时存在；同一天最多安排一场主要的同期生日庆祝活动；是否记得生日，根据同期的人设、关系及是否知道玩家生日决定；情缘人物不计入上述好友人数，也不受这套同期生日分支限制；玩家可以决定是否接受邀请以及如何回应。

### 02｜入社三个月后的宿舍重新分配 🏠

**触发时间**：玩家正式入社满 3 个月。**必定触发一次。**

公司通过 KKT 或宿舍公告通知练习生，进行宿舍安排调整。

**可能结果**：① 维持原状（玩家和原室友都不需要搬）② 部分调整（某位室友搬走，或有新室友搬进来）③ 重新分配（玩家被安排到其他房间）。具体结果由现有宿舍情况、人物关系和公司住宿安排决定。

**剧情内容**：系统需要在「此刻」演绎这次宿舍重新分配。如果发生搬迁，可以出现整理行李、告别原室友、认识新室友等内容。如果没有变化，也应当有查看分配名单、与室友讨论结果的剧情。

**不强制玩家换宿舍，也不保证一定与好朋友住在一起。** 注意：这与条件生活剧情「室友突然退社」是两个不同事件，不得混淆。

### 03｜练习生集体外出 🎡

**触发时间**：建议正式入社满 2 个月后，由公司安排一次。**整个练习生阶段固定安排一次。**

公司组织部分练习生参加集体休闲活动。活动形式可能包括：游乐园、海边旅行、郊游、野餐、其他合理的集体活动。地点不固定，参与人数不要求覆盖全部 39 位女同期。

**剧情规则**：公司提前通过 KKT 或相关通知公布安排；活动进入日历和提醒事项；到活动当天，通过「此刻」展开实际剧情；参与人员依据公司安排及实际情况决定；同期之间的互动根据真实性格与人物关系发展；可以认识此前并不熟悉的同期；不强制发生矛盾、友情升温或其他特定结果。

### 04｜第一次放长假 🧳

**触发时间**：玩家正式入社后，首次遇到公司安排的连续两天及以上正式假期。**首次触发一次。**

可以沿用游戏已有的中秋、春节等节假日及放假安排，不另外创造一套假期制度。

**剧情内容**：公司提前通知假期安排。不同同期可能回家探亲、留在首尔、和朋友外出、安排自己的私人活动。通过「此刻」演绎放假前后的实际生活情境。

**规则**：不强制玩家回家或外出；由玩家自行决定假期如何度过；同期的假期安排应符合她们的家庭背景、居住情况及实际日程；不能只在日历里标记放假而没有相关剧情。

### 05｜首尔初雪 ❄️

**触发时间**：游戏世界当年首尔第一次下雪。**每年首次初雪必定触发一次。**

**触发方式**：不固定地点。无论玩家当时在练习室、宿舍、街道、便利店或其他合理地点，都应当根据当前场景衔接初雪剧情。

**剧情规则**：系统检测首尔当年的首次降雪；在合理的时间节点触发初雪专属演出；保留此前已经设计的初雪动画、韩中双语文案及视觉效果（**尚未实现，本次一起做**）；根据当前所在位置、同行人物和正在进行的活动衔接「此刻」剧情；独处、与朋友同行、与同期同行或正在约会，可以有不同发展；不强制出现特定人物，不强制恋爱发展；不为了触发初雪强行改变玩家当前位置。若当前正在进行重要剧情，应合理衔接，不得直接覆盖尚未结束的场景。

### 06｜年末家族聚餐 🎄

**触发时间**：第一年 12 月，公司年末家族演唱会结束后。**作为固定事业主线「年末家族演唱会」的后续固定生活活动，必须发生。**

**参与人员**：根据公司实际安排，可能包括女练习生、男练习生、已出道女团前辈、已出道男团前辈、老师、公司工作人员。不要求所有人物全部到场。

**剧情内容**：公司组织年末聚餐。具体聚餐地点、座位安排、人物互动和谈话内容，由当时的实际人物及关系决定。此前在课堂或其他活动中认识的前辈，可以自然再次出现。

**规则**：与年末家族演唱会使用同一条连续时间线；不额外举办一场重复的公司年会；不强制每位前辈认识玩家；不预设聚餐必定发生冲突、表白或其他戏剧事件；通过「此刻」实际演绎聚餐。

### 07｜春日樱花季 🌸

**触发时间**：次年春天，首尔樱花盛开期间，通常为 3 月下旬至 4 月上旬。**每年樱花季固定触发一次。**

**剧情形式**：不安排公司统一赏樱活动。系统根据当前人物关系、地点和日程决定合理的展开方式。例如：好朋友通过 KKT 邀请玩家赏樱、某位同期临时约玩家出门、玩家在外面偶然遇见熟悉的人、玩家在忙碌的训练间隙欣赏樱花、玩家独自经历某段春日场景。

**规则**：不固定邀请者、不固定同行人物、不固定赏樱地点、不强制玩家接受邀请；即使没有外出，也可以在当前地点演绎春日樱花剧情；不能与出道选拔或正式行程发生无法解释的时间冲突。

### 08｜夏日暴雨 🌧️

**触发时间窗口**：第一年 7 月下旬至 8 月底。**该时间窗口内必定触发一次。**

**日期选择**：系统读取该时间窗口内可用的首尔天气数据。优先选择**降雨最强的一天**作为夏日暴雨事件的触发日。如果无法提前获得完整窗口的天气数据，应采用可执行的天气判定方案，在窗口内实际出现的强降雨日安排事件，避免错过整个触发窗口。

**剧情内容**：当天根据玩家当前的位置、行动、同行人物和天气状况生成暴雨剧情。可能出现：下课后因暴雨暂时无法离开、与同期或朋友一起寻找避雨地点、原本的外出安排受到天气影响、在街道、便利店或其他地点经历一段突如其来的雨天故事。

**规则**：不固定地点或参与人物；不强制玩家和某个人一起避雨；不预设特定情感发展；不能为了触发事件强行改变玩家位置；当天通过「此刻」演绎实际天气与生活场景。

### 09｜秋季大学音乐节 🍁🎤

**触发时间**：第一年秋季，9～11 月内安排一次。**每个练习生阶段固定举办一次。**

**活动设定**：首尔某所大学举办音乐节，邀请多组已出道爱豆或其他歌手演出。活动重点是：观看爱豆舞台、现场音乐节氛围、粉丝应援及观众互动、练习生视角下的演出体验。

**触发流程**：

- **第一阶段：活动排期**——系统在秋季确定一场真实存在于游戏世界中的校园音乐节。将活动信息加入世界日历。
- **第二阶段：邀请或主动参加**——优先由符合条件的同期通过 KKT 邀请玩家。邀请者根据兴趣、双方关系及日程选择，不固定。即使没有人邀请，玩家也可以通过日历得知活动，自行决定是否参加。
- **第三阶段：音乐节当天**——若玩家决定参加，则通过「此刻」演绎实际音乐节场景。同行者由玩家实际接受的邀请和后续安排决定。玩家可以选择与同期同行、邀请别人或独自参加。

**与情缘线的避让规则**：另有「校园男生情缘线」中的大学庆典节点。两个事件必须区分：

- 校园男生情缘线：校园摊位、社团活动等大学生活体验；和对应男主的关系发展；包含校园草坪看星星等既定情缘节点。
- 秋季固定生活剧情：以观看爱豆演出的大学音乐节为核心；同行人物不固定；不要求情缘关系参与。

排期时：不得使用同一所大学的同一场庆典来重复充当两个事件；尽量将两场活动错开至少 14 天；如果情缘节点尚未符合条件，固定音乐节照常发生；不得因为固定音乐节已经举行，就自动完成情缘大学庆典节点；情缘节点之后仍然可以根据羁绊进度独立安排。

## 三、额外固定课堂剧情

### 入社第一天｜老师介绍新练习生

**触发条件**：玩家正式签约后，第一次进入公司练习室参加课程。**必定触发一次。**

**剧情内容**：老师向玩家当前班级的其他练习生介绍新来的成员。玩家开局为 C 班，因此首次介绍发生在 C 班。其他同期此前已经在公司训练，彼此拥有真实的认识关系。

**规则**：老师如何介绍玩家，由实际人物背景和教学风格决定；同期如何回应，由她们各自的性格和关系决定；玩家有机会认识部分同期，但不强制一次认识所有人；已经通过其他剧情认识的人物，不重新当作陌生人介绍；不替玩家决定自我介绍的具体内容或个人态度；这段剧情与 55 段普通课堂固定文本分开，不参与普通课堂文本随机抽取；在老师完成介绍后，可以自然衔接当日正常课程。

## 四、统一触发与排期规则

1. **固定剧情必须有明确触发来源**：世界日期、入社时间、已经确定的公司活动、首次符合条件的假期、世界天气或季节变化、玩家生日。不得完全依赖 AI 自己想起某个固定事件。
2. **三种触发入口**：KKT（通知、邀请、活动安排和需要玩家提前回应的事件）；此刻（用于实际演绎事件，玩家进入合理的场景时，系统根据事件状态、当前地点和人物关系开展剧情）；日历／提醒事项（用于已确定日期的活动及玩家已经接受的安排。活动被添加进日历，不代表玩家已经参加，也不代表剧情已经完成）。
3. **不强制替玩家做决定**：固定活动必定存在于世界中，但不代表玩家必须参加每一场自愿活动。如果玩家拒绝邀请，活动仍然可以发生，只是不应生成玩家实际参加的经历。对于初雪、樱花、暴雨这类季节节点，即使玩家不参与额外活动，也应当根据玩家当时的实际场景呈现相应的季节剧情。
4. **固定事业主线优先避让**：正式课程、周评与月考；已确定的试镜、正式拍摄与演出；年度固定事业主线；其他已经接受的正式行程。如果时间发生冲突，应该合理安排生活剧情的通知、准备或演绎时间。不得直接取消已确定的重要主线。
5. **根据人物真实关系生成**：生活剧情中的人物不固定，但必须符合当前实际认识关系、同行及在场情况、人物性格与背景、已经发生的共同经历、当前世界时间和人物日程。不得为了触发事件强制让某位 NPC 出现在不合理的地点。
6. **固定剧情结果必须保存**：生日有哪些同期参加了聚会、宿舍调整后实际和谁同住、集体外出认识了哪些人、初雪当天与谁在一起、家族聚餐与哪些前辈交流、樱花季发生了什么、暴雨是否影响了原定行程、音乐节是否参加、与谁同行。这些事实可以被后续剧情、KKT 聊天和人物关系引用。

## 六、最终设计原则

固定生活剧情提供练习生生活中的重要时间节点和季节仪式感。系统必须保证事件被合理安排、通知及演绎，但不预先规定玩家一定如何经历这些事件。

**代码负责触发与排期，AI 负责人物与故事，玩家决定自己的行动。**

同一事件可以因为玩家的关系、位置、背景和经历不同，在不同存档中呈现完全不同的故事。
